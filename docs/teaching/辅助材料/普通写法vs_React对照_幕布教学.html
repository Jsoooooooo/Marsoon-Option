普通写法 vs React

同一件事，两种活法 —— 看完就能分清。
按 → 开始，第一幕就能亲手点一个「点赞」按钮试试。
第 1 幕 · 细节：同一个"点赞 +1"，代码长什么样

左边你亲手改界面，右边你只说"该长这样"

点它 → 左边红点会一格格手动跑完，右边只亮 ①、②③ 自动完成
同一件事，用 Excel 表格看 👇
普通 · 没有公式，全靠手填
点赞数显示颜色
0 👍 0 灰
点一下 → 这 3 格都要手动改
React · 只有点赞数是数据，其余是公式
点赞数 数据显示颜色
0 =👍&数量👍 0 =数量%2?红:灰灰
点一下 → 只改"点赞数"，显示/颜色自动重算
点上面按钮：左边按 ①→②→③→④ 一格格点亮（你得亲手做这么多步），右边只亮 ①、②③ 自动跑完——这就是"改界面"和"改数据"的区别。
第 2 幕 · 一个数量，三处同步（就像 Excel · 可交互）

加一件：普通改 3 处，React 只改 1 处

就像 Excel：左边每格都是手填的死数字，右边只有"数量"是数据、其余是公式，改一处自动重算
同一件事，用 Excel 表格看 👇
普通 · 没有公式，全靠手填
数量商品行顶部角标合计
0 0 0 ¥0
加一件 → 这 4 格都要手动改
React · 只有数量是数据，其余是公式
数量 数据商品行顶部角标合计
0 =数量0 =数量0 =数量×单价¥0
加一件 → 只改"数量"1 格，公式格自动重算
Excel 能"改一格、别处自动变"，是因为你事先写了公式（依赖）。React 做的是同一件事：只声明一次"谁等于谁"，数据一变，所有引用它的地方自动重算。
完成 · 一句话

普通 改界面，React 改数据

记住这一句就够了 —— 数据一变，界面自动跟着变。
回朋友：React 不是"把 HTML 拆成组件"，而是让你只管数据、界面交给它同步。
